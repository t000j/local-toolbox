# PDF processing: current partial scope

Tool 61 merges 2–8 local files in the visible list order and keeps each source's page order. It uses pinned `pdf-lib` 1.17.1 (MIT), loaded only in a Worker. Input is ≤8 MiB/file and ≤16 MiB total; output ≤16 MiB and ≤200 pages. The UI uses a 30-second Worker deadline with cancel, edit/clear and navigation termination. Saving uses the existing Windows create-only binary output, with no automatic overwrite/open/upload.

## Supported subset and rejections

This is deliberately **partial**. Canonical PDF 1.0–1.7 with classic cross-reference tables or bounded single-save object/xref streams, direct stream lengths and supported static pages is admitted. Ordinary PDFs with hybrid/incremental cross-reference structures, encrypted content, forms/signatures, annotations/links, actions/JavaScript, embedded/external files, navigation/bookmarks, optional layers, tagging or document-level OutputIntents are rejected. No password bypass or silent flattening is attempted. Conservative checks can reject valid documents, including names whose spelling creates parser ambiguity.

Before library parsing, the code validates PDF syntax, lengths, object definitions/references, xref offsets and EOF. Object/xref structural streams are independently decoded in16KiB chunks and validated before rewriting a classic-xref admission copy. A second preflight scans decoded names, including `#XX` spelling, even inside byte payloads, so compressed structural parsing paths cannot reach pdf-lib. Strict bounds include 6,000 objects, 100,000 syntax/graph nodes, depth32, strings64KiB and page-tree depth24. The raw scanner can intentionally produce false positives.

After loading, object identities must match preflight, no library recovery is accepted, the page tree must be acyclic with correct Parent/Count, and supported objects are audited. Resource fingerprinting is cycle/depth/size bounded; it compares original stream bytes and canonical resource dictionaries rather than decoding them. MediaBox/CropBox/BleedBox/TrimBox/ArtBox, rotations and positive UserUnit (≤75,000) are validated. After save, a fresh preflight/load/audit checks page count and every page's SHA-256 content/resource/property fingerprint in order.

Page content/resources are preserved, not malware-sanitized. A malicious compressed image/font/content stream may remain dangerous to a later PDF reader even though this app does not render or decompress it. Use trusted inputs. Document metadata/identity and viewer preferences are not retained; visible content and page metadata can still contain private information. This is neither anonymity processing, compression nor PDF/A conversion. Bounds reduce work but are not an absolute process-memory guarantee.

## Evidence and remaining gaps

- `scripts/check-pdf-merge.cjs`: synthetic classic-xref inputs, encoded/indirect stream-type rejection before library load, damaged references/xref, cycles, excessive limits, unsupported features, page order, geometry, contents/resources and output reparse
- `scripts/check-derived-ui.cjs`: simulated file reordering, acknowledgment, stale results, duplicate saves and navigation
- Independent Poppler verified a three-page synthetic merge: ALPHA1, ALPHA2, BRAVO1, with differing page geometry and 90° rotation; all three source/output raster PNGs were byte-identical
- No real user PDFs were read. Windows dialogs/create-only IO, WebView UI and clipboard remain unverified; cloud local-browser access was blocked and not bypassed

Broader object-stream variants, forms/annotations, richer document structures and broader PDF variants remain open, so the roadmap marks this tool partial. Library reference: [PDFDocument API](https://pdf-lib.js.org/docs/api/classes/pdfdocument) and [load options](https://pdf-lib.js.org/docs/api/interfaces/loadoptions).

## Page extraction (62, partial)

Read and audit one ≤8 MiB source, then select comma-separated page numbers or ascending ranges, e.g. `1-3,5`. Selection order is output order; overlap, duplicate pages, descending ranges, empty tokens and out-of-range pages are errors. Export one new PDF per selection; repeat for additional parts. Page count/geometry is shown, not content thumbnails. Source bytes remain unchanged. Output is reloaded and fingerprints must match every selected source page, including its original rotation. The same format/feature limitations above apply. Synthetic Poppler output for source pages 4 and 2 matched each source raster byte-for-byte. Mock editor tests cover edits, cancellation state, duplicate saves and stale save completion; actual UI/native saving remains untested.

## Bounded object/xref-stream admission (shared by61–64)

Support is deliberately specific: one final XRef stream, direct parameters and stream lengths, unique objects and complete matching type1 offsets/type2 stream indices; no hybrid xref, encryption or incremental updates. ObjStm and XRef may be raw or single-Flate; XRef supports single-channel8-bit PNG predictors10–15. Per structural stream decoded≤1MiB, total decoded≤4MiB, total encoded≤2MiB, streams≤128, objects≤6000. The existing pinned pako1.0.11 is now explicit. It streams16KiB chunks, aborts before retaining an over-budget chunk, requires a true zlib end/checksum, and rejects trailing/concatenated or truncated input. Canonicalization preserves ordinary page/resource stream bytes; it does not sanitize them. The canonical copy has a16MiB limit and must pass the original classic preflight and loaded-object audit. Generated object-stream sources and their admission copies have identical Poppler rasters and page/resource fingerprints.

## Page sorting and content thumbnails (63, partial)

Reorder by original-page identity with up/down controls, including across the12-page display groups. Export always includes every page exactly once; no duplicate/deletion capability is implied. Whole-output page fingerprint order is checked after save. Preview is explicit, cleared on reorder/file changes and never embedded through a PDF viewer/plugin. No PDF JavaScript, annotation actions, XFA or script sandbox is instantiated.

Thumbnails use pinned Mozilla PDF.js6.2.108 legacy API/worker builds. Its [2026 security advisory](https://github.com/mozilla/pdf.js/security/advisories/GHSA-hq66-cqwq-w95j) identifies6.2.108 as patched; we also avoid the scripting-enabled viewer entirely. Each run gets an explicit real Worker port, no silent main-thread parser fallback; XFA/WASM/system-font fallback/font-face loading/worker resource fetching are disabled. A build-time whitelist serves only bundled standard font assets; arbitrary CMap/WASM/font URLs are refused. PDF.js and font license texts ship in `public/licenses/`. Optional Node canvas packages in the lockfile support CLI evidence only, not the WebView bundle. No npm audit transmission was repeated for this batch; the changed lockfile therefore does not inherit the previous batch’s zero-advisory claim.

Before preview, decoded resource bytes are capped at32MiB and2000 streams. Only unfiltered/single-Flate streams are accepted; DecodeParms, F/DP aliases and image W/H/BPC/IM/CS aliases are rejected. Any BI byte pair is conservatively rejected, even in harmless strings/binary data, to prevent inline images bypassing the stream gate. FunctionType/PatternType/ShadingType and Mask/SMask resources are rejected to exclude sampled allocations and procedural tiling/shading. These preview-only limits reject many valid image/gradient/font-bearing PDFs; exporting the same supported document can still work. Images≤1MP/2048edge, intermediate canvases≤1MP each/4MP live,12 thumbnails≤256 longest edge and4MiB PNG total. Preparation30s and rendering20s are separately cancelled; old blob URLs and canvases are released. Parser/font/internal allocations and main-thread rendering are not universally memory/time bounded. The low-resolution white-background preview is approximate and can differ in fonts/color from a full viewer.

Synthetic tests cover resource bombs, aliases, inline-image bypasses, sampled resources, cancellation/deadlines, worker destruction and save state. Actual PDF.js with optional native Node canvas rendered synthetic text pages and matched their extracted/reordered output RGBA byte-for-byte; independent Poppler also matched every reordered source/output page. This is rendering-library evidence, not a browser/WebView or Windows end-to-end UI test.

## Page rotation (64, partial)

Each page has a0/90/180/270° clockwise delta; optional all-page buttons set a starting delta before individual edits. Zero preserves the original rotation, not a forced absolute0°. The interface shows original and final angles. This modifies page Rotate only, preserving content/resource bytes, all page boxes, page order and UserUnit; it does not rasterize, resample or move drawing coordinates. The exported document is reloaded and compared against the precisely rotated expected page fingerprints. Input/output/page/Worker/save limits and static-document restrictions match the shared editor.

Synthetic checks cover different original angles, negative/over360° rotations, inverse restoration, unaffected boxes/resources, per-page/all-page controls, stale save states and malformed worker requests. Independent pypdf rotations of the same synthetic sources rendered identically with Poppler on all four output pages. Actual WebView interactions and Windows native dialogs remain unverified.

## Image-quality compression (65, partial)

Quality10–95 controls lossy JPEG re-encoding of embedded image resources, not whole-page rasterization. Eligible images are proven image-only direct-page XObjects,8-bit DeviceRGB, no mask/alpha/ICC/custom decode parameters, ≤4096edge/4 million pixels. Raw or single-Flate RGB bytes must match dimensions exactly; JPEG requires three channels, orientation1, no embedded ICC and matching dimensions. Unsupported image keys/codecs remain byte-identical and are counted/reported. JPEG candidates are validated and replace a resource only when their encoded byte count is smaller. If no resource changes, the entire result is byte-identical to the source. PDF rewriting overhead can still outweigh image savings; the UI reports actual sizes without promising reduction.

The PDF retains selectable text, vector operators, page geometry/order/rotation and non-replaced resources. Sources with links/annotations/forms/signatures or other unsupported document structures are rejected by admission, never silently flattened. The image encoder can change colors, compression artifacts and JPEG metadata; this is lossy and does not provide privacy cleaning. Input≤8MiB, output≤16MiB, ≤200pages/64images/16 million processed pixels total, serial Worker encoding and30s deadline. Before any encoding, all incoming uses of image streams and Resources/XObject containers are classified. Any non-image alias (Contents, ToUnicode, Metadata, arrays, indirect aliases or another semantic container), Form-only or orphan image is kept unchanged. Original page-content/non-resource fingerprints are captured before mutation and must still match after save, independently of the exact post-change resource fingerprints. A malicious stream tagged Image and shared as page Contents is a regression fixture; it never reaches the codec and the source PDF stays byte-identical. Synthetic Pillow JPEGs + pure-core injection verify replacements; independent pypdf confirms text/raw drawing operators/boxes remain unchanged. Canvas cleanup tests are mocks; browser codec and Windows IO remain unverified.

## PDF pages to PNG/JPEG (66, partial)

Select1–8 unique pages in the requested order,36–300DPI, and PNG or JPEG quality10–100. PDF.js uses CropBox, original Rotate and UserUnit; each visible page is rasterized against white. Output is pixels: text/search/link/vector semantics are not retained in images. DPI determines viewport pixels at dpi/72; browser encoders may write default print-density metadata instead of the requested DPI. PNG preserves the rendered pixels, not necessarily original PDF colors/fonts or transparency.

Admission, bounded stream checks, parsing, rendering and encoding all run inside one dedicated outer Worker. The bundled PDF.js local/loopback transport is intentionally inside that killable worker, not a main-thread fallback or an unowned nested worker. OffscreenCanvas/2D/DOMMatrix/Path2D/ImageData must exist there; missing capabilities fail closed. DOM/SVG filter requests throw rather than silently changing rendering. Only exact bundled-font assets may be fetched; no document external resources, scripting viewer, XFA, WASM or font-face loading. The UI terminates the worker on cancel/edit/navigation/error or30s timeout.

Bounds:8MiB input,200 source pages,4096px edge/4 million pixels per output,16 million total rendered pixels,16 million live canvas pixels and32MiB encoded images. Oversized requests reject before output-canvas allocation rather than lower DPI. Existing32MiB predecoded stream bounds and narrow preview-resource restrictions still apply, including rejection of encoded JPEG/JPX input resources, predictors/aliases, BI spelling, masks, sampled functions, patterns/shadings and unsupported CMaps. This is a useful static-text/vector subset, not general PDF rendering. Limits and termination are not an absolute browser-process memory guarantee.

The main receiver independently validates PNG/JPEG magic/structure, encoded dimensions/orientation, order and byte/pixel totals. UI previews use revocable blob URLs and each image is saved explicitly with create-only IO. Actual PDF.js with a native-canvas OffscreenCanvas-compatible shim verified synthetic PNG/JPEG output, independent decoding, page order, crop/90°rotation/UserUnit,72/144DPI and preallocation rejection; visually inspected synthetic ALPHA/BETA outputs. Worker/UI lifecycle is mocked. Actual browser-worker capability/behavior and Windows saving remain unverified.

## Static PNG/JPEG images to PDF (67)

One image per page, ordered by the visible list. Normalize EXIF orientation including mirrored cases through the decoder’s from-image option and verify the oriented dimensions. Choose A4/Letter (auto/portrait/landscape) or physical size from pixels and explicit36–300DPI, plus0–50mm margins. Fit is contain/center only: no stretching/cropping, though small images may be enlarged on standard paper. Image-sized pages add margins around the pixel/DPI dimensions and ignore original density tags.

PNG preserves the normalized8-bit Canvas alpha; JPEG deliberately flattens on white at quality10–95. Original metadata/ICC blocks are not copied. Canvas may change color/high-depth/HDR meaning, so no archival color or original-pixel-encoding guarantee is made. Animation and non-PNG/JPEG formats reject. Image text remains raster data, without OCR or selectable text.

Per-image16MiB/4096edge/4 million pixels;1–8 images,32MiB input and16 million pixels total; prepared data and PDF each≤32MiB;45s terminable Worker. Before pdf-lib’s PNG decoder, validate canonical8-bit RGB/RGBA noninterlaced structure, allowlisted chunks, exact bounded IDAT zlib size and row filters. Prepared PNG/JPEG dimensions must match, with orientation1 and no animation. Output is reloaded to verify page count/geometry/rotation and embedded image count/dimensions. No source modification, automatic upload/save or overwrite.

Synthetic core tests check fit/margins/physical dimensions, alpha and RGB embedded bytes, ordering, immutable inputs and malformed/bomb limits. All eight color/alpha pixel centers in a high-resolution Poppler rendering matched independent Pillow compositing exactly; small4×2 one-pixel-per-source-pixel rendering shows reader interpolation, not a claim of raster identity at every zoom. Orientation1–8 decoder options/dimensions and JPEG white-background cleanup are simulated; real browser mirrored pixels/normalization and Windows IO remain unverified.

## Selectable text extraction (68, partial)

A dedicated, terminable worker loads and audits the static PDF, applies the conservative preview stream gate, then reads PDF.js streamed text chunks. It does not perform OCR. Page selection preserves requested order (1–50 unique pages); separators identify original pages. Item sequence and hasEOL are preserved, but PDF.js normalizes whitespace/Unicode and content-stream order can differ from visual columns, tables, bidirectional text or rotated layout. Missing text can mean image-only pages or unusable font mappings; verify important output.

Input8MiB/200 source pages,32MiB predecoded streams,100,000 text items,1 million UTF-16 code units,4MiB UTF-8 output,30s worker deadline. Only exact bundled standard-font assets may load; external CMap/fonts, scripting and remote document URLs are unavailable. The same static-document and narrow resource restrictions as preview apply, so common unsupported PDFs are rejected rather than silently flattened. Worker termination bounds runtime but is not a universal process-memory guarantee. New-file-only TXT saving, revision/cancel/unmount guards, no automatic persistence.

Actual PDF.js synthetic extraction tests cover requested page order, deliberately reversed visual column order, accented text/euro, empty pages and UTF-8. Accumulator bounds and Unicode tests do not prove universal font/bidi fidelity. UI/worker lifecycle is simulated; real browser/WebView and Windows save remain unverified. API reference: https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html
